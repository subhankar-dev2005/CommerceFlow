## 4. Validation Design (Zod)

Defined in `src/modules/users/admin-customer.validator.js`:
- Numeric fields (`page`, `limit`) are coerced safely using `z.coerce.number().int()`.
- `limit` strictly enforced between 1 and 50.
- `search` is trimmed and bounded to 100 characters.
- `status`, `sortBy`, and `sortOrder` are strict enums with descriptive validation error messages.
- Any malformed input produces a standard 400 `VALIDATION_ERROR` response via `validate.middleware.js`.

## 5. Search Security & ReDoS Prevention

- Customer search supports querying both `name` and `email` with `$or` semantics:
  ```javascript
  const trimmed = req.query.search.trim();
  if (trimmed) {
    const escaped = escapeRegex(trimmed);
    const searchRegex = new RegExp(escaped, "i");
    filter.$or = [{ name: searchRegex }, { email: searchRegex }];
  }
  ```
- **ReDoS Protection:** User input is processed via `escapeRegex` (`src/utils/escape-regex.js`), escaping all regex metacharacters (`.*+?^${}()|[\]\\`).
- **Role Isolation:** Search can never cross-pollinate into admin accounts because `{ role: 'customer' }` is enforced at the root of the MongoDB filter.
- **Status:** `[VERIFIED]`

---

## 6. Status Filtering & Role Isolation

- Customer role isolation is unconditionally enforced:
  `filter.role = "customer"`
- Account status mapping:
  - `status === 'active'`: `filter.isActive = true`
  - `status === 'inactive'`: `filter.isActive = false`
  - `status === 'all'`: no `isActive` restriction (returns both active and inactive customers).
- Administrators are **NEVER** returned by this endpoint under any condition, search term, or status filter.
- **Status:** `[VERIFIED]`

---

## 7. Deterministic Sorting

- Whitelisted fields: `createdAt`, `name`, `email`.
- Primary sort direction: `1` (asc) or `-1` (desc).
- Secondary tie-breaker: `_id: sortDirection` is appended to all sort queries.
- Prevents nondeterministic pagination pagination anomalies (e.g. records jumping between pages due to identical timestamps).
- **Status:** `[VERIFIED]`

## 8. Pagination Implementation

- Server-side calculation: `skip = (page - 1) * limit`.
- Total count: `await User.countDocuments(filter)`.
- Total pages: `Math.max(Math.ceil(totalCustomers / limit), 1)`.
- Navigation flags:
  - `hasNextPage: page < totalPages`
  - `hasPrevPage: page > 1`

## 11. Index Usage & Performance

The queries issued by `getAdminCustomers` match the indexes added in Step 79.2:
1. `status=all`:
   `{ role: 'customer' }` sorted by `{ createdAt: -1, _id: -1 }`
   Supported by index: `{ role: 1, createdAt: -1 }`.
2. `status=active` or `status=inactive`:
   `{ role: 'customer', isActive: true|false }` sorted by `{ createdAt: -1, _id: -1 }`
   Supported by index: `{ role: 1, isActive: 1, createdAt: -1 }`.
3. No N+1 queries: Address, Order, and Review collections are not queried during listing.
