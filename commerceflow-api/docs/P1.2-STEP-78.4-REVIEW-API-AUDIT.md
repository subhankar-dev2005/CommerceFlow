## 1. Endpoints Implemented

The customer-facing review API is mounted on `productRoutes` under `/:productId/reviews`, resolving to:

| HTTP Method | Route Endpoint | Middleware Stack | Purpose |
| :--- | :--- | :--- | :--- |
| **POST** | `/api/v1/products/:productId/reviews` | `authMiddleware`, `validate(createReviewSchema)` | Creates a new verified-buyer review for the product. |
| **GET** | `/api/v1/products/:productId/reviews` | `authMiddleware`, `validate(reviewQuerySchema)` | Retrieves public, published reviews for the product with pagination and sorting. |
| **PATCH** | `/api/v1/products/:productId/reviews/:reviewId` | `authMiddleware`, `validate(updateReviewSchema)` | Updates the authenticated customer's own review. |
| **DELETE** | `/api/v1/products/:productId/reviews/:reviewId` | `authMiddleware`, `validate(reviewParamsSchema)` | Deletes the authenticated customer's own review. |

---

## 2. Authentication Behavior

- Every customer review endpoint is strictly guarded by `authMiddleware`.
- Unauthenticated requests immediately yield HTTP `401 Unauthorized` (`AUTH_TOKEN_REQUIRED` or invalid token).
- The authenticated user identity is derived purely from `req.user._id` (JWT session), never accepted from client payloads or route parameters.

---

## 3. Create-Review Flow

When `POST /api/v1/products/:productId/reviews` is invoked:
1. **Validation:** `createReviewSchema` enforces `rating` (integer 1–5), `title` (optional, max 100), and `body` (min 5, max 2000). Rejects any client-injected fields (`user`, `order`, `isVerifiedBuyer`, `status`).
2. **Product Existence:** Checks `Product.findById(productId)`. Returns `404 PRODUCT_NOT_FOUND` if nonexistent.
3. **Purchase Verification:** Calls `findQualifyingOrder(req.user._id, productId)`. If ineligible, returns `403 REVIEW_PURCHASE_REQUIRED`.
4. **Duplicate Prevention:** Checks if the user has already submitted a review for this product. Returns `409 REVIEW_ALREADY_EXISTS`.
5. **Creation:** Sets `isVerifiedBuyer: true` and `status: "published"` server-side. Records `order: qualifyingOrder._id`.
6. **Recalculation:** Calls `recalculateProductRating(productId)` to update `Product.ratingAverage` and `Product.ratingCount` atomically.
7. **Response:** Returns `201 Created` with review data (excluding qualifying order ID).

---

## 4. Purchase Verification Integration

- Controller delegates directly to `findQualifyingOrder(userId, productId)` in `review.service.js`.
- Enforces server-authoritative qualifying purchase:
  - `order.user == userId`
  - `order.status == "delivered"`
  - `order.payment.status == "paid"`
  - `order.items` snapshot contains `productId`
- Client never provides `orderId`, preventing tampering or IDOR attempts.

---

## 5. Duplicate-Review Handling

- **Application Check:** Pre-checks `Review.findOne({ user: req.user._id, product: productId })` before insert.
- **Database Unique Invariant:** MongoDB compound unique index `{ user: 1, product: 1 }` guarantees that concurrent parallel `POST` requests fail gracefully on duplicate key constraint (E11000 mapped to `409 REVIEW_ALREADY_EXISTS`).

---

## 6. Public Review Filtering

- Public `GET /api/v1/products/:productId/reviews` strictly queries `{ product: productId, status: "published" }`.
- Hidden and flagged reviews are completely excluded from customer results.
- Optional rating filter (`req.query.rating`) filters by exact integer rating ($1-5$).

## 8. Ownership Enforcement & Update/Delete Behavior

### PATCH
- Verifies review exists and matches `productId`. If missing or wrong product scope, returns `404 REVIEW_NOT_FOUND`.
- Verifies `existingReview.user.toString() === req.user._id.toString()`. If non-owner, returns `403 REVIEW_ACCESS_DENIED`.
- Restricts updates to `rating`, `title`, and `body`. Client cannot alter `product`, `user`, `order`, `isVerifiedBuyer`, or `status`.
- Invokes `recalculateProductRating(productId)` after update.

### DELETE
- Verifies review exists under product scope (`404 REVIEW_NOT_FOUND`).
- Verifies review ownership (`403 REVIEW_ACCESS_DENIED`).
- Executes hard deletion: `Review.findOneAndDelete({ _id: reviewId, product: productId, user: req.user._id })`.
- Invokes `recalculateProductRating(productId)`. If the deleted review was the last published review, metrics reset to `0 / 0`.

## 9. Error Mapping

All errors conform to CommerceFlow's `AppError` and centralized error middleware:

| Status Code | Error Code | Description |
| :--- | :--- | :--- |
| **400** | `VALIDATION_ERROR` | Malformed ObjectId or invalid request body/query fields. |
| **401** | `AUTH_TOKEN_REQUIRED` | Missing or invalid Bearer token. |
| **403** | `REVIEW_PURCHASE_REQUIRED` | Authenticated user has not received and paid for this product. |
| **403** | `REVIEW_ACCESS_DENIED` | Non-owner attempting to edit or delete another user's review. |
| **404** | `PRODUCT_NOT_FOUND` | Target product does not exist in database. |
| **404** | `REVIEW_NOT_FOUND` | Review ID does not exist within target product scope. |
| **409** | `REVIEW_ALREADY_EXISTS` | User has already submitted a review for this product. |
