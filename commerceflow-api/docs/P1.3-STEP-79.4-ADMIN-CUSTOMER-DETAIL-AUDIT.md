## 3. Customer Profile & Role Isolation

- **Customer-Only Query Constraint:**
  ```javascript
  const customer = await User.findOne({
    _id: customerId,
    role: "customer"
  })
    .select("_id name email role isActive createdAt updatedAt")
    .lean();
  ```
- **Admin Isolation:** If an administrator account ID is passed as `:customerId`, the query matches 0 documents and returns 404 `CUSTOMER_NOT_FOUND`. Administrator profiles cannot be inspected via the customer detail endpoint.
- **Safe Projection:** Explicitly projects only non-secret operational fields (`_id`, `name`, `email`, `role`, `isActive`, `createdAt`, `updatedAt`). Passwords, password hashes, JWTs, and security fields are **never** selected or exposed.
- **Status:** `[VERIFIED]`

## 5. Order Statistics Semantics

- **Aggregation Pipeline:**
  ```javascript
  Order.aggregate([
    { $match: { user: new mongoose.Types.ObjectId(customerId) } },
    {
      $group: {
        _id: null,
        totalOrders: { $sum: 1 },
        totalSpent: {
          $sum: {
            $cond: [
              {
                $and: [
                  { $ne: ["$status", "cancelled"] },
                  { $eq: ["$payment.status", "paid"] }
                ]
              },
              "$total",
              0
            ]
          }
        },
        lastOrderDate: { $max: "$createdAt" }
      }
    }
  ])
  ```
- **Metric Definitions:**
  - `totalOrders`: Total count of all orders placed by the customer (inclusive of all statuses).
  - `totalSpent`: Total persisted currency amount of all non-cancelled, successfully paid orders (`status !== 'cancelled'` and `payment.status === 'paid'`). Cancelled or unpaid orders do not contribute to spending.
  - `lastOrderDate`: Chronological timestamp of the customer's most recent order placement (`$max: "$createdAt"`).
- **Default/Zero State:** If the customer has placed 0 orders, safely returns:
  `{ totalOrders: 0, totalSpent: 0, lastOrderDate: null }`.
- **Status:** `[VERIFIED]`

## 6. Recent Order Semantics

- **Bounded Query:**
  ```javascript
  Order.find({ user: customerId })
    .sort({ createdAt: -1 })
    .limit(5)
    .select("_id status payment.status shipment.status total totalQuantity createdAt")
    .lean()
  ```
- **Summarized Payload:**
  - `id`: Order ID string
  - `status`: Fulfillment status (`pending`, `confirmed`, `processing`, `shipped`, `delivered`, `cancelled`)
  - `paymentStatus`: Payment status (`pending`, `paid`, `failed`, `refunded`)
  - `shipmentStatus`: Carrier shipment status (`label_created`, `in_transit`, etc., or `null`)
  - `total`: Authoritative monetary total
  - `itemCount`: Total quantity of items in the order
  - `createdAt`: Order timestamp
- **Security:** Strips out internal Razorpay IDs, payment signatures, restoration keys, and full product items arrays.
- **Status:** `[VERIFIED]`

## 11. Validation Design

- Implemented in `src/modules/users/admin-customer.validator.js`:
  ```javascript
  export const customerIdParamSchema = z.object({
    body: z.object({}).optional(),
    query: z.object({}).optional(),
    params: z.object({
      customerId: z
        .string({ invalid_type_error: "Customer ID must be a string" })
        .regex(/^[0-9a-fA-F]{24}$/, "Invalid customer ID format")
    })
  });
  ```
- Non-24-character hexadecimal IDs immediately fail before hitting the database, returning 400 `VALIDATION_ERROR`.
- **Status:** `[VERIFIED]`
